# AGENTS.md — Frontend (`front`)

## Назначение
- `front/` — основной пользовательский frontend проекта.
- Django templates и связанные с ними UI routes/HTMX handlers выведены из эксплуатации и удаляются.
- Django остается backend: Ninja API, модели, сервисы и фоновые задачи.

## Обязательные правила
- Работать только в `front/`, если пользователь явно не попросил иное.
- Использовать только `Svelte 5` syntax с runes.
- Использовать только runes-подход: `$state`, `$derived`, `$effect`, `$props`, snippets и т.д.
- Не использовать устаревший синтаксис Svelte 3/4.
- Все UI-элементы строить на базе `shadcn-svelte`.
- Если нужного UI-компонента из `shadcn-svelte` нет, сначала попросить пользователя установить его.
- Не заменять отсутствующий `shadcn-svelte` компонент самодельным крупным кастомным виджетом без необходимости.

## Технический стек
- `SvelteKit`
- `Svelte 5` (runes only)
- `shadcn-svelte` как обязательная UI-база
- Backend API для нового frontend: `django-ninja`

## Архитектурная модель
- Новый frontend работает поверх Django backend.
- Основной backend app для миграции сейчас: `vault`.
- Основной паттерн интеграции:
  - `front` page/component
  - при необходимости SvelteKit proxy route в `front/src/routes/api/*`
  - `django-ninja` endpoint в `vault/api.py`
- Модели и сервисный слой Django по возможности сохраняются.
- Frontend должен использовать Ninja API; Django templates/views старого UI не восстанавливать.

## Текущее состояние
- Перенос UI в новый frontend завершен. Реализованы:
  - список фильмов
  - sidebar-фильтры
  - поиск
  - сортировка
  - страница фильма
  - страница персоны
  - системные статусы
  - рейтинг
  - добавление/удаление фильма в пользовательские списки на странице фильма
  - TMDB sync flow
- TMDB sync flow уже поддерживает:
  - `ok`
  - `needs_confirmation`
  - `needs_user_choice`

## Навигация и загрузка данных
- Проект используется как локальное single-user desktop/self-hosted приложение.
- Для этого проекта глобальный `SSR` может быть отключен и уже считается допустимым решением.
- Допустим SPA-ориентированный UX без SEO-ограничений.
- Внутренние переходы должны оставаться SvelteKit-навигацией, без полного reload.
- Layout должен оставаться стабильным и не пересобираться тяжелым способом без необходимости.
- Фильтры, поиск и сортировка должны стакаться через query params.

## Практические правила для новых задач
- Если задача относится к новому UI, сначала проверять, есть ли уже endpoint в `vault/api.py`.
- Если endpoint нет, сначала добавлять его в backend, затем подключать во frontend.
- При переносе сценариев `vault` не менять модели без явной необходимости.
- Не добавлять новые пользовательские страницы на Django templates.
- Для действий пользователя в detail/list-сценариях предпочитать маленькие, конкретные endpoint-ы.
- Перед использованием нового UI-компонента проверять, установлен ли он в `front/src/lib/components/ui/`.
